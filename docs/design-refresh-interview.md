# デザイン刷新 (3Blue1Brown 風) のインタビュー記録

クラウドセッションで行ったインタビューの途中経過。ローカルセッションでこの続きから進める。

## 現状のデザインの性質

- `template/src/ui.tsx` の部品 (`Scene` / `Box` / `Flow` / `Code` / `FileTree`) は「見出し + 箱と矢印のスライド」の作り
- シーン間は `fade` のクロスフェードで切り替わり、要素は `usePop` / `useFadeIn` で現れるだけ
- 品質チェックは各シーン最後の静止画を Claude が読む方式で、動きそのものは検証していない

3Blue1Brown の洗練は、配色やフォントよりも動きの文法による部分が大きいという見立て:

- 同じ物体がシーンをまたいで残り、変形・移動して次の概念になる (カットやフェードがほぼない)
- 画面には常に 1 つのアイデアだけがあり、見出しや説明文の帯がない
- 図形が「描かれる」(線のストローク描画、文字の書き出し、トランスフォーム)
- 語りと動きがフレーム単位で同期している

## 決まったこと

- **目指す深さは未定。** 次の 3 段階を、実際に作って見比べて決める
  1. 見た目の統一: 配色・タイポグラフィ・余白・図形のトーン
  2. 描画の質感: スライド構成は残し、線の描画・文字の書き出し・要素の移動などのアニメーションの質を上げる
  3. 動きの文法: 物体がシーンをまたいで残り、変形しながら話が進む。見出しや字幕帯をなくす (`ui.tsx` と `assemble` の作り直しが必要)
- **既定を「音声あり」に変える。** 字幕モードで他の人に使ってもらったとき「音声はできないのか」と聞かれ、音声ありが期待値だと分かったため。字幕モードは選択肢として残す
- **エンジン (Remotion のまま / Manim に移行) は見比べてから決める。** Claude の推奨は Remotion のまま (中身はコード・ファイル構成・処理の流れが中心で、Manim の強みである数式・グラフが活きる場面が少ない。既存の組み立て・ナレーション同期・チェックの仕組みを活かせる)
- **見比べは 2 段階で行う**
  1. 「処理の流れ」のシーン 1 つで、Remotion の 3 段階と Manim 版を作り、深さとエンジンを決める
  2. 決めた方式で残りの 3 種類 (コードの解説・全体構成・設計の「なぜ」) を作り、苦手な種類がないか確かめる
- **題材は `aijnek/ocr_human_review_skill`。** 以前この題材で動画を 5 本作った。作業ディレクトリ (原稿・`.tsx`・ナレーション音声) は Mac の `~/.cache/onboarding-video/ocr_human_review_skill*/` にあり、旧版との直接比較に使える
- **サンプルの書き出しと TTS は Mac で行う** (Qwen3-TTS / MLX は Apple Silicon でしか動かないため)

- **動きの検証はコマ並べ画像で行う。** シーンごとに等間隔で 6〜8 コマを 1 枚に並べ、Claude が読む。途中の重なり・変形の破綻・出るタイミングの偏りを見る
- **配色・フォントは 3B1B に寄せつつ独自に調整する。** 黒に近い背景・青/茶/黄のアクセント・細めの線という文法は借り、色値はコードの可読性と日本語フォントとの相性で調整する
- **`SKILL.md` の書き換えは深さが決まってから決める。** 段階 1/2 なら部品と自己チェック手順の差し替え、段階 3 なら c (映像) の書き方から変わるため

## 見比べ 1 段階目 (処理の流れ)

題材は旧版 JobQueue の 3〜5 番目のシーン (アップロードで 2 行書く → ロングポーリング → running に書き換える)。旧版のナレーション音声をそのまま使う。3 シーンにまたがるので、段階 3 の「物体が残って変形する」効果が出る。

作業ディレクトリは Mac の `~/.cache/onboarding-video/design-refresh/` (旧版の作業ディレクトリの複製)。

- `out/samples/Stage1.mp4`〜`Stage3.mp4`: Remotion の 3 段階 (`src/samples/`)
- `out/samples/Manim.mp4`: Manim 版 (`manim/jobqueue.py`)。段階 3 と同じ絵コンテ
- `tools/sheet.sh`: コマ並べ画像を作る (動画の区間から 8 コマを 4x2 に並べる)

Manim を動かすには、Homebrew の `pkgconf` が必要だった (pycairo のビルドに使う)。

## 1 段階目の結論

- **深さは段階 3 (動きの文法) にする**
- **エンジンは Remotion で仮決めする。** 文字・コード・表が主役で、字幕モードと時刻の直しやすさを残せるため。2 段階目で、Remotion の部品が膨らむほど「形の変形」が要ると分かったら、Manim を考え直す

## 見比べ 2 段階目

### コードの解説

題材は旧版 ReviewFlow の 6〜8 番目のシーン (確定の関数 → なぜ両方残すか → 幻の修正)。`src/samples/CodeExplain.tsx`、`out/samples/CodeExplain.mp4`。

わざと変形の要る演出を入れた: コードの語 `extracted` / `corrected` が表の列名になる。列名 `value_corrected` が精度の指標になる。修正の 1 行がコードに割り込み、下の行を押し下げる。

- 部品の追加は「飛ぶ」部品 (`Fly`、約 30 行) だけで済んだ。字形そのものの変形は要らず、「語が飛んで、着いてから前に `value_` を書き足す」で足りた
- 手間がかかるのは、エンジンではなく座標。3 シーンで約 370 行あり、旧版 (3 シーンで約 75 行) の 5 倍。大半は要素の位置の指定で、Manim でも同じだけかかる。段階 3 を `SKILL.md` に落とすときは、座標の決め方 (格子、表やコードの行の位置を返す補助関数など) を用意する必要がある

## 修正に入る前に決めたこと

- **エンジンは Remotion に決定。** サンプル題材の動画全体は作り直さない。残り 2 種類 (全体構成・設計の「なぜ」) のサンプルも作らず、刷新後のスキルで実際に作ったときに直す
- **動画は「場面」ごとに連続させる。** ナレーション 2〜4 行を 1 場面にし、場面の中では物体が残って変形する。場面の間は、物体を消してから次を描く。1 場面 = 1 コンポーネント
- **字幕モードをやめる。** 音声なしの動画は作らない。代わりに、ナレーションの原稿と長さから mp4 の隣に `.srt` を書き出す (アクセシビリティのため。画面には焼き込まない)
- **タイトルと「次のステップ」は中身をそのままに、新しい見た目で作り直す。** それぞれ 1 場面の共通部品
- **旧部品 (`Scene` / `Box` / `Flow` / `Arrow` / `usePop` / `useFadeIn`) は消す。** `Code` と `FileTree` は段階 3 用に作り直す
- **座標は「位置を返す部品」で扱う。** `Code` / `FileTree` / `Table` は置く座標を受け取り、行・セル・語の位置を返す。画面の安全領域と配置の目安を `SKILL.md` に書く

## 修正の内容

- `template/src/ui.tsx`: 段階 3 の部品 (描く・書き出す・入れ替える・飛ぶ、位置を返す `Code` / `FileTree` / `Table`、新しい見た目のタイトルと次のステップ) と、場面の組み立て `video()`。旧部品と字幕の組み立てを消した
- 動きの確認: `<id>-sheet` コンポジションで、1 行ごとに 6 コマを並べた画像を書き出す。Remotion 同梱の ffmpeg には `tile` などのフィルタがないため、並べる処理も Remotion で行う
- `template/scripts/srt.mjs`: 字幕ファイルの書き出し。原稿の `{表示|読み}` は表示の側を使う (`narrate.py` は読みの側を読む)
- `SKILL.md` / `README.md`: 字幕モードの記述を消し、場面割り・動きの文法・配置・コマ並べによる確認の手順を書いた
